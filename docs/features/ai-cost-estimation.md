# AI原価査定機能

**文書管理情報** | 作成：2026/04/03 中原 | Dokuly実装設計：2026/04/21

## 1. 思想（実現したい世界）

RFQ、開発/設計、原価企画、調達/購買とプロセスおよび部門を横断して扱われる「原価」について、プロセス・部門横断でデータを環流し、適切に活用な状態で変換させていくことで、全社/事業最適な判断を迅速かつ、誰でも判断できる状態＝**原価最適化判断の民主化**を目指す。

特に上流においては、下流情報も踏まえた原価最適化のための設計・提案を簡易かつ低コストにシミュレーション・検証を行える環境を作ることで（例：仕様をA→Bにした場合のコスト影響をその場で特定する）諦めざるを得ないコスト最適な設計や下流の製造性やFBを加味した企画・提案・設計の実現を支援する。

## 2. 概要

「適正な原価判断」を行う主要なプロセスである、RFQ・開発/設計時のコストレビュー・原価企画/管理、調達原価査定において**「類似品と原価比較」**および**「AIによる工程推論を起点とした原価推論」**を組み合わせることで、原価判断をしたい品目に対しての妥当な原価を提示し、各プロセスでの判断材料に繋げる。

RFQ〜原価企画〜調達までを横断活用させていくことでデータの環流と複数ユースケースでの業務実装を行いスイッチングコストを高める。

## 3. プロジェクト情報

| 項目 | 内容 |
|------|------|
| **経営テーマ** | ・原価競争力強化と調達コスト最適化による利益向上<br>・見積LT短縮 |
| **KPI** | ・原価低減目標の達成率向上(+20%)<br>・発注前の原価企画活動の実施率(+100%)<br>・初期コストからの原価低減金額<br>・査定L/T(現状比50%短縮) |
| **主なユーザー** | ・調達部門<br>・原価企画/設計部門（見積を行う部門・担当者） |
| **最大ユーザー数** | ・調達: 100名（デンソーを例に）<br>・原価企画: 50名<br>・設計: 1,000名 |
| **対象業務** | **調達**: サプライヤ見積の査定・既存品の原価低減活動・変化点コスト管理<br>**原価企画/設計**: 開発品のRFQ向けの原価計算・新規品の原価試算・変化点コスト管理・原価改善ネタの洗い出し、集計、改善進捗管理 |
| **今回スコープ外** | ・Assy・内製品の対応<br>・設計・原価企画向け集計機能等<br>・図面形状変更等のVAVE提案<br>・原価改善のプロジェクトマネジメントなど |

## 4. 業務フロー

### 全体フロー

```
⓪ 初期ベースデータ構築
   ↓
① プロジェクト作成・妥当原価判断対象の設定
   ↓
② 差異分析・妥当性判断
   ↓
③ 改善提案(工程・サプライヤ)・シミュレーション
   ↓
④ 交渉実行・再見積もり
   ↓
⑤ 単価確定・稟議資料用データの出力＆社内簡易レビュー
```

### 詳細フロー

#### ⓪ 初期ベースデータ構築

**目的**: 過去データを取り込み、AI推論のベースラインを作成

**処理内容**:
1. ユーザーが過去分の参考データを登録
   - データ種類：3D-CAD、2D図面、QC工程表、見積明細書（PDF, Excel）、発注実績
2. 各書類を読み取り、書類種別を分類すると共に、品番・図番等の指定キーをもとにリレーションを作成
3. 各図面の工程表から情報を読取・構造化
4. 読取項目のマスタ作成を行う（例：原材料費＝材料費 と読み替える等）
5. ユーザーが項目マスタを確認・修正

**技術要件**:
- ファイル形式：Excel・PDF・3D形式・JPEG等（ポンチ絵も対応）
- ファイルサイズ：1ファイル5MB程度（標準外はエラー出力）
- データ規模：
  - 1カテゴリで500図面 × (図面1 + QC工程表1 + 見積明細書3) × 2回見積取得 = 5,000枚
  - 5~10カテゴリで25,000〜50,000枚
  - カテゴリ例：プレス・樹脂・ダイカスト・ゴム・ブロック・旋盤・板金・鋳物
- 処理時間：大量データで1週間程度OK
- ⚠️ 途中確認が必要（1週間後に失敗判明は避けたい）

#### ① プロジェクト作成・妥当原価判断対象の設定

##### 1-0. 案件管理画面

**機能**:
1. URLにアクセス
2. 案件の進捗状態が見える
   - **作業者視点**: 起案中、査定中、見積回収中、稟議レビュー
   - **レビュー者視点**: 未対応・完了済
   - 1回目見積 or 2回目見積の表示
3. 作業者は「新規作成」ボタンを押す
4. 作業者は「データ取り込み」を押すと⓪の画面へ

##### 1-1. 図面・見積価格を入力する

**機能**:
1. ユーザーが新規プロジェクトを作成
2. 作成したプロジェクトに各種情報を登録
   - 当該図面の2D/3D + 品目リスト等
   - 査定回答がある場合：見積明細書（PDF/Excel）等
   - 見積回答がない新規：無し
3. 情報の読み取り結果がプリセットされる
   - 品番、部品名、サプライヤ名、数量
   - 見積総額、各工程費用など
4. ユーザーに完了通知をメール、システム通知
5. ステータスを「起案中」に変更
6. ユーザーがプリセットされた項目を手入力/修正
   - 量産系は工程別アコーディオン有
7. **多工程対応**
   - 多工程の見積（プレスはA社・塗装はB社）は競合しない工程のため足し算
   - サプライヤの組み合わせはユーザーで選択
8. **見積書読み取り**
   - 見積書記載のサプライヤからのコメントも備考欄として提示かつ、データに蓄積

**技術要件**:
- ファイルサイズ：上限1ファイル20MB、合計60MB（画像が重いケース等がある）
- 処理が切れた場合、部分再計算を行う
- 解析はGeminiで5分以内を想定
- ⚠️ 予算設定・入力が諸々必要

##### 1-2. 比較対象を決定する

**機能**:
1. 原価妥当性判断の目的パターンの設定と、当該品目情報から類似品目を検索し初期候補を提示
   
   **目的パターン**:
   - 妥当原価の推論
   - 見積結果の妥当性推論
   - 妥当原価・改善余地の特定
   
   **類似候補パターン**:
   - 形状類似（図面）
   - 最大寸法（図面）
   - 図面諸元：材質・表面処理・幾何公差数値/種類・溶接有無（図面）
   - 工法：材質 × 公差 × 工程からロジック + 推論（図面＆見積書）
   - サプライヤ（見積書）
   - 図面の詳細差分から類似度順に提示
   - 流用元品目が指定されている場合は、流用元品目を第1位の比較対象として提示

2. 初期候補に対し、諸元・数量等のフィルタ調整によって対象品目の調整を行う
3. 手動入力で比較対象を追加できる
   - 図面・明細内容のプレビューを見れる
   - 過去分の査定ページに飛べる
4. ユーザーがどれと比較するかを選択決定できる

**AIアルゴリズム（比較対象の選択）**:

| ステップ | 処理 | 詳細 |
|---------|------|------|
| Step1 | 形状類似（Drawer） | 上位20件を取得 |
| Step2 | メタデータフィルタ | 材質・表面処理・寸法±30%のAND条件。0件→自動段階緩和（±50%→±70%）。緩和条件はUI上に明示 |
| Step3 | 複合スコアランキング | 形状類似70% ／ メタデータ一致20% ／ 工法類似10%（⚠️仮置き） |

##### 1-3. 現在の価格の妥当性チェックを実績ベースで提示する

**妥当原価判断の場合**:

1. ステータスを「査定中」に変更
2. 当該図面に対し、当該図の加工工程（見積書・図面から推定）に基づきコストに影響する詳細な図面差分をLLMで整理
3. 2で設定された図面差分から、コスト判断材料として適用するものをユーザーで決定・修正・追加
4. 類似品目との形状差分に対し、過去のサプライヤの見積結果・見積明細書にあるロジック・LLMの純粋な知見から妥当な価格を推定
   - 流用元品目がある場合は、図面の変化点に対してのコスト変化点の影響を推論する
5. 当該図面価格（選択した比較先価格）が、AIによる差分の推定価格差分に対して妥当かどうかを判定
6. AIの原価推論および差分からの原価妥当性チェックに加え、**比較類似品目の原価レンジ（箱ひげ図）**も参照することでAI提示の原価や差分判断の妥当性チェックを行う
   - 多品種少量を中心とした見積もり明細が存在しないケースにおいてはこの箱ひげ図でのダブルチェックが特に求められる
7. ユーザーは以下を編集する
   - 比較に入れたくない加工工程があれば縦の集計から排除（A製品は処理があるが、B製品は処理がない等）
   - チャージ/工数等の推定計算ロジックが表示され、数値等を編集する
   - 金型・治具等の費用について、24均等・ライフ数量割・寿命割・計算除外等が選び、全体コストの算出に反映できる

**原価改善余地特定の場合**:

1. ステータスを「査定中」に変更
2. 以下2パターンで原価低減余地を提示
   - 最新のAI推論原価との差分とその要因仮説
   - 類似品目の最安ケースとの比較
3. 提示された仮説・比較品目について、改善材料として取り入れるかの対象選択および手修正を行う

**技術要件**:
- 2の解析はGeminiで処理
- 4, 5の解析はGeminiで10分以内を想定
- 結果をExcel・PDFで出力
- ⚠️ 出し先サプライヤーのとりまとめ機能は欲しい

##### 1-4. ベスト価格の提示＆改善提案を複数パターンで提示する＆シミュレーション

**機能**:
1. 過去のデータ + Geminiの推論から、よりよい改善パターンとそこから見込まれる効果金額を提示
   - サプライヤの変更
   - 工法の変更
   - 工程の変更
   - ⚠️ 過去データない部分でもLLMの実力値で改善の論点出しをさせる
2. 複数のパターンを統合した場合のポテンシャルコストを提示
3. ユーザーは、採用する改善を入れて、今回の図面で採用できそうな選択肢を選び、自分なりのシミュレーションを行う
4. Excel等で出力可
5. ステータス入力を実施して、「見積もり結果待ち」に変更する

**技術要件**:
- 1, 2の解析は10分以内を想定

**将来的な拡張**:
- BOM構成や上位の仕様から全然違う図面書いてるけど同じでいけるのでは？的提案もしたい
- 装置系は部品まとめて改善この十個はこれです
- 改善提案系の1部品の、横展開したときさらにやれる

#### ④ 交渉実行・再見積もり

##### 2-0. サプライヤへの見積依頼実施

- 操作画面は無し
- シミュレーション等をベースに新規サプライヤ選定して見積もり、提案した改善案をサプライヤに提案など実施する

##### 2-1. 取得した回答結果を改めて査定する

**機能**:
1. 追加したい見積・図面を入力
2. 同一図面の場合、引き継がれる内容が表示される（類似これと比較してこうだったよね）
3. 図番が変わる（設変・流用図）もので、過去の案件を引き継ぎたい場合は、図番等を入力
4. 引継ぎを選択
5. ステータスを「2回目見積・起案中」に変更

##### 2-2. 妥当性確認

- 基本的には1-3と同一

##### 2-3. 改善提示・ベスト工程提示

- 基本的に1-4と同一

#### ⑤ 単価確定・稟議資料用データの出力＆社内簡易レビュー

##### 3-1. 稟議書類作成

**機能**:
1. 稟議用書類が出力
   - 基本は妥当性判断 + 選択したベスト工程が採用される
2. どの列を比較として採用するかを選択
3. 稟議コメント内容を入力
   - 各工程
   - 全体
   - 選定理由
   - 今後のコストダウンに向けてetc
4. データの出力ができる
5. メールを自動で発射できる
   - アドレス帳から読むか、自動発射

##### 3-2. 稟議書類社内レビュー

**機能**:
1. 送られたリンクを開く
2. レビュー用画面が表示
3. 担当者の判断根拠にコメントを入れる
   - 比較査定対象・各工程の査定・今後のコストダウン展望、サプライヤ選定に対して
4. 担当者は、査定過程を見ることができる
   - 1-2にてどの比較対象を選んだのか?
   - 1-3にてどんなAIの提案があったか?
   - 1-4にてどんな改善をこの担当者が取得しているか?
5. 完了を送る

**技術要件**:
- ⚠️ レビューユーザーの画面検討（Quoteの承認プロジェクト管理）

## 5. データの循環フロー（学習ループ）

### 結果データの取得

1. **比較データ**
   - 類似品だけでなく、設計変更前・2回目見積vs1回目見積等も比較できるようにして、前回提案結果がどういう着地になったかデータをとれるようにする
   - 最終価格は稟議資料作成等に使える資料化することで、結果データの入力がなされるようにする
   - 稟議資料化することで、なぜその価格になったか?の理由もわかる

### 中間プロセスの決定データ

1. **類似候補レコメンド改善**
   - 出した類似候補と実際に顧客が選択した比較候補で、提出順序のレコメンドを改善

2. **改善パターンレコメンド改善**
   - 改善パターンの提示と実際にシミュレーションがなされた内容でレコメンド改善

3. **ダークデータの蓄積**
   - AIの仮説に対しての取捨選択やユーザーの追加情報を蓄積し、「どういうケースで何が有効なものだったか」のダークデータに繋げる
   - 判断結果を次回の類似ケースに当てはめていくことで「無駄な検討」を最小化していき、「AI時代の情報量過多」に対しての改善策に繋げていく
   - 継続利用によるログ・ダークデータでのロックインに繋げる
